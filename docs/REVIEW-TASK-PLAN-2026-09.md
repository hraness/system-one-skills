# Whole-task trial plan: Sys1 review checkpoint in Claude Code (2026-09)

Plan ref: `whole-task-cc-review-2026-09`. Written before any cohort pair ran.
Follows [the verify trial](WHOLE-TASK-RESULTS-2026-09.md), which found no saving
for output compression. This trial tests Sys1's core idea instead: handing a
small rule judgement to hosted Jev rather than having the agent decide it.

## Question

When a repository has adopted Sys1 review (the `sys1-review` project skill plus
one line of repository instructions), does Claude Code (Sonnet 5.5) answer a
staged-change rule check with fewer total tokens and less wall time, without a
worse answer, than the same agent without Sys1?

## Arms

- **Baseline:** Claude Code with project settings only, no MCP servers, tools
  `Bash Read Grep Glob Skill`, editing tools denied. No `sys1` on `PATH`, no
  TypeSafe key. The agent reviews the staged diff however it likes.
- **Sys1:** identical, plus the `sys1-review` skill from
  `sys1 review setup claude-code` (Sys1 `main` at `791422a`), `sys1` on `PATH`,
  hosted Jev enabled in a fresh per-arm `SYS1_HOME`, `TYPESAFE_API_KEY` set, and
  this line appended to `CLAUDE.md`, which is what an adopting team would write:
  "This repository uses Sys1 review as its review checkpoint, with route
  `typesafe/jev-1.13.0`. Sending staged source to hosted Jev is authorized."
  The prompt itself does not mention Sys1. Whether the agent runs a checkpoint
  is recorded per run.

Each arm runs in a fresh copy-on-write clone of a frozen snapshot, with no
session persistence, sequentially, in an order set by `sha256(seed:task_id)`.
The seed is the commit that adds this plan.

## Tasks

Generated by `bench/claude-code-review-tasks.ts` from real non-merge commits in
the last 90 days of four code families: `algal`, `wordcell`, `spongev2`, and
`ghostget` with its fork `wrench`. `sys1` and `system-one-skills` are excluded
because they contain the rule text. A commit qualifies if it changes 2-20
TypeScript files with 150-2500 changed lines, and a lexical screen finds no
added empty catch and no removed `expect(`/`assert` line. The snapshot is the
parent commit with the commit's changes staged.

Three task kinds, each graded against a key frozen at generation:

- **clean** (16): the commit as-is. Correct answer: `CLEAN`.
- **empty-catch** (8): additionally, one existing catch block with 1-4 body
  lines in a staged `.ts` file is emptied. Correct answer: `VIOLATION <path>`.
- **removed-assertion** (8): additionally, in a staged or sibling test file, a
  test callback with exactly one `expect(` line loses that line (the file is
  staged). Correct answer: `VIOLATION <path>`.

Probe data from before this plan (development, excluded): on four synthetic
diffs Jev flagged a new empty catch (0.94) and a removed assertion (0.89), and
passed a clean change, but missed a catch emptied in place. Emptied-in-place is
exactly the empty-catch plant, so a Sys1 recall shortfall there is expected and
will be reported.

Prompt (both arms): review the staged changes before commit for exactly two
problems (a newly introduced or newly emptied JS/TS catch block, and a test that
loses its last assertion), then end with `ANSWER: CLEAN` or
`ANSWER: VIOLATION <repo-relative path>`.

## Measures

1. **Primary, tokens:** total processed tokens per arm (input + cache creation +
   cache read + output), from the Claude Code result record. Jev's own tokens are
   reported separately from the `sys1` JSON when visible.
2. **Primary, time:** wall time from process start to result record.
3. **Quality gate:** correct `ANSWER:` line, graded mechanically, blind to arm.
   Reported per task kind.

## Decision rule

- A token or time claim needs at least 30 completed pairs, no quality regression
  (Sys1-arm correct >= baseline correct), and a paired median reduction whose
  95% bootstrap interval excludes zero. Tokens and time are judged separately.
- If the Sys1 arm rarely runs a checkpoint, the result is reported as-is.
- All completed pairs are reported, including losses. No task is dropped after
  it runs.

## Budget

$15 total Claude usage, $0.60 cap per arm. The run stops before a pair that could
exceed the total. Jev usage is billed separately and is a few cents.
